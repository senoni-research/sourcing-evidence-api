What explains the price change?

A supplier requests an increase. This API makes the declared cost drivers inspectable, shows a conditional price scenario, and withholds the calculation when the evidence does not support a comparison.

Engineering choices

Evidence first. Arithmetic in code.

FastAPI · typed validation · decimal arithmetic

01 / INPUT

Document or JSON

Small PDF/text uploads or structured facts enter the API. Input limits constrain the demonstration.

02 / EXTRACT

Typed facts + sources

The labelled-template parser supplies facts, page references and quotations. Source identity and text are checked.

03 / CHECK

Comparability gates

Schema, quote scope and evidence completeness determine whether a calculation is permitted.

04 / REVIEW

Deterministic scenario

Decimal arithmetic returns contributions, explicit status, questions and an analysis fingerprint.

Labelled-template extraction is the default. No model call was used in these recorded cases.

An optional OpenAI-compatible adapter can extract typed facts; it does not do the arithmetic or execute tools. Provider behaviour was tested with mocked responses. Live model extraction accuracy has not been validated.

Interpretation & scope

A useful result includes its boundaries.

Assumptions behind the scenario

  • Baseline price moves proportionally with the declared index basket.
  • Cost shares are assumed; margin, FX, hedging and productivity are held constant.
  • Annual volume is an illustration, not committed demand or realised savings.

What the result can establish

  • This is a conditional index-basket scenario, not a verified supplier should-cost estimate.
  • The gap is a discussion point, not evidence of overcharging or a saving achieved.
  • Shares, indices and annual volume are supplied inputs; their commercial validity requires human review.
  • The model assumes the baseline price moves proportionally with the declared basket; margin, hedging, productivity, contracts and FX may change the result.
  • Evidence excerpts establish traceability, not independent verification or semantic correctness.

Prototype boundaries

  • All documents, supplier details and indices are fictional. There is no connection to any real buyer, procurement systems or live market data.
  • The default parser requires the published labelled format. There is no OCR. GBP is the only supported scenario currency.
  • The API can withhold a calculation; it does not approve prices, contact suppliers or create purchase orders.
  • Local operation is the demonstrated scope. Public uploads require isolated document processing, enterprise access controls and deployment review.
  • Requests are processed in memory. There is no durable audit store, tenant isolation or production operational history.
